# 四层是嵌套关系（外层包含内层），不是替代关系

> 本条目是「认知升级：四层模型」的第 7 部分，对应学习清单条目 1.2.3。
>
> **前置依赖**：四层模型整体认知
> **为以下铺垫**：后续所有方法论学习

---

## 一、核心观点

> **四层是嵌套关系（外层包含内层），不是替代关系**：新层出来，旧层变成它的子集，不是作废。即「外层包含内层」——Loop 包含 Harness 包含 Context 包含 Prompt，详见下方嵌套关系图。

## 三、「包含」与「不是替代」的含义

- **Prompt 在 Context 中**：Prompt 是模型看到的上下文的一部分
- **Context 在 Harness 中**：Context 运行在 Harness 提供的环境里
- **Harness 在 Loop 中**：Harness 是 Loop 的一个执行单元
- **都不会过时**：每次调用仍要 Prompt；信息管理、生产环境、自动化永远需要

> ❌ 错误理解：「有了 Context，Prompt 不重要了」「有了 Loop，Harness 不需要了」
> ✅ 正确理解：四层是**补充**不是**替代**，按依赖顺序逐层学

## 五、实践中的应用

设计 Agent 系统时**逐层思考**：

1. **Prompt 层**：指令怎么写？
2. **Context 层**：模型需要看到什么信息？
3. **Harness 层**：Agent 需要什么工具和权限？
4. **Loop 层**：如何设计自动化循环？

> 项目答辩/技术评审时，可逐层展开「我的项目在四层都做了设计」，展示系统思维（见 [[10-画出四层模型演进图|四层模型演进图]]）。

## 速记卡（面试闪卡）

**Q1：一句话讲清「四层是嵌套关系（外层包含内层），不是替代关系」到底是什么？**
A：四层是嵌套关系：新层出来旧层变子集而非作废，Loop 包含 Harness 包含 Context 包含 Prompt。

**Q2：一、核心观点 —— 怎么理解？**
A：像俄罗斯套娃：大娃套小娃，外层把内层装进去，不是把旧娃扔了。新出的 Loop 层只是把 Harness、Context、Prompt 一层层裹进来，旧层依然是它的子集，照样天天用。

**Q3：二、嵌套关系图 —— 怎么理解？**
A：像公司四级架构：CEO(Loop)管总监(Harness)管经理(Context)管一线(Prompt)。级别越高包得越宽，但一线的活（写 prompt）永远存在，不会因为有了 CEO 就取消。

**Q4：三、包含不是替代 —— 怎么理解？**
A：像盖楼：地基(Prompt)被楼层(Context)包住，楼层被大楼(Harness)包住，大楼被园区(Loop)包住。楼越高地基越重要——没人会说"有了园区就不需要地基"。

**Q5：四、每层的定位 —— 怎么理解？**
A：像四代工具演进：Prompt(2022 改措辞)、Context(2025 管信息)、Harness(2026 搭环境)、Loop(2026 设计自循环)。层层登场，老层当新层的子集，按依赖顺序学最稳。

**Q6：核心速记主线有哪些？**
- 四层嵌套：Loop 含 Harness 含 Context 含 Prompt，外层包内层
- 不是替代：新层出，旧层变子集，仍天天用、不过时
- 逐层思考：Prompt→Context→Harness→Loop 设计 Agent
- 时间线：2022 Prompt → 2025 Context → 2026 Harness/Loop

**口诀**
A：四层如套娃，外层裹内家；
新层添子集，旧技莫弃他。
Prompt 打地基，Loop 管天下；
逐层往上爬，系统才不垮。
