# 多 Agent 死循环检测与预防

> 多 Agent 系统中，Agent 之间可能互相等待或互相触发，形成死循环。这比单 Agent 的循环更难检测，因为循环跨越了多个 Agent 的边界。

## 死循环的典型模式

### 互相委托

```text
Agent A: "这个问题应该问 Agent B"
    ↓
Agent B: "这个问题应该问 Agent A"
    ↓
Agent A: "这个问题应该问 Agent B"
    ↓ （无限循环）
```

### 任务回传

```text
Agent A 完成任务 → Agent B 审查 → 发现问题 → 退回 Agent A
    ↓
Agent A 修改 → Agent B 审查 → 发现新问题 → 退回 Agent A
    ↓ （无限循环）
```

## 三层检测方案

### 架构层检测

| 机制 | 说明 |
|------|------|
| 通信轮数限制 | 设置最大消息传递次数 |
| 拓扑分析 | 运行前检测环路 |
| 角色约束 | 限制哪些 Agent 可以互相通信 |

### 逻辑层检测

| 机制 | 说明 |
|------|------|
| 消息重复检测 | 检测相同内容是否重复发送 |
| 参数重复检测 | 检测相同参数的工具调用 |
| 任务状态追踪 | 检测任务是否在相同状态间循环 |

### 监控层检测

| 机制 | 说明 |
|------|------|
| 超时机制 | 整个流程超时强制终止 |
| 成本监控 | 超过预算强制停止 |
| 日志分析 | 实时分析 Agent 通信日志 |

## 预防策略

| 策略 | 说明 |
|------|------|
| 明确职责边界 | 每个 Agent 有清晰的职责范围 |
| 设计终止条件 | 每个任务都有明确的完成标准 |
| 引入裁判 Agent | 第三方 Agent 判断是否陷入循环 |
| 降级处理 | 检测到循环时切换到单 Agent 模式 |
