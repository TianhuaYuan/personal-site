# 10：安全加固四道防线

## 概述

从 API 鉴权、输入校验、MCP 传输、CLI 路径四个维度构筑安全防线。

---

## 第一级：四道防线总览

| # | 防线 | 机制 | 关键代码 | 防护目标 |
|---|------|------|----------|----------|
| 1 | **JWT 鉴权** | HS256 access token + is_valid_token | `core/security.py` + `api/auth.py` | API 端点和 MCP 网关防匿名调用 |
| 2 | **CLI 路径穿越防护** | `Path.resolve()` + `relative_to()` 校验 + 密钥文件名黑名单 | `cli/main.py:_resolve_review_file` | CLI --file 防读取系统文件 |
| 3 | **Prompt 注入防护** | supervisor 代码审查 prompt 中固化输出格式 + 审查而非执行指令（架构性防护） | 待加固 | 防恶意代码操控 LLM 输出 |
| 4 | **MCP BearerAuthMiddleware** | ASGI 层 Bearer token 拦截，开发态放行/生产态必须有效 JWT | `main.py:_BearerAuthMiddleware` | /mcp 路径防未授权调用 |

## 第二级：防线详解

### 防线 1：JWT 鉴权

📍 `core/security.py`：`is_valid_token`、`create_access_token`
📍 `api/auth.py`：API auth

**security.py**（30 行→实际 50 行）：

```python
_ALGO = "HS256"

def create_access_token(subject: str, expires_minutes=None) -> str:
    payload = {"sub": subject, "iat": now, "exp": now + exp * 60}
    return jwt.encode(payload, settings.JWT_SECRET, algorithm=_ALGO)

def decode_token(token: str) -> dict:
    return jwt.decode(token, settings.JWT_SECRET, algorithms=[_ALGO])

def is_valid_token(token: str | None) -> bool:
    if not token:
        return False
    try:
        decode_token(token)
        return True
    except jwt.PyJWTError:
        return False
```

设计要点：
- 签发/验证集中在一处，API 与 MCP 共用
- `is_valid_token` 把解码异常归一化为布尔，方便依赖/中间件直接判断
- 默认 `API_AUTH_REQUIRED=False`（开发态便利）；生产环境设 True + 自定义 JWT_SECRET
- 单操作者工具，省 refresh token，只发 access token

**auth.py**（23 行→实际 36 行）：

```python
@router.post("/auth/token")
async def issue_token(req: TokenRequest):
    if settings.API_AUTH_REQUIRED and req.api_key != settings.API_KEY:
        raise HTTPException(status_code=401, detail="invalid api_key")
    token = create_access_token("operator")
    return TokenResponse(access_token=token)
```

- 用 API_KEY 换取有时效的 JWT Bearer token
- 开发态（API_AUTH_REQUIRED=False）：任何人可换 token
- 生产态（API_AUTH_REQUIRED=True）：必须提供正确的 API_KEY

### 防线 2：CLI 路径穿越防护（cli/main.py）

📍 `cli/main.py`：路径穿越防护

```python
_SECRET_FILENAMES = {".env", "id_rsa", ...}
_SECRET_SUFFIXES = (".pem", ".key", ".p12", ...)

def _resolve_review_file(file: str) -> Path:
    repo_root = Path(__file__).resolve().parents[2]      # cli/main.py → backend → 仓库根
    path = Path(file).resolve()
    path.relative_to(repo_root)                          # 必须在项目目录内（防 ../../etc/passwd）
    if name in _SECRET_FILENAMES or name.startswith(".env.") or name.endswith(_SECRET_SUFFIXES):
        raise ValueError(...)                             # 拒绝密钥文件
    return path
```

- `Path.resolve()` 解析符号链接/相对路径为绝对路径
- `relative_to()` 校验：必须位于项目目录内（防路径穿越）
- 密钥文件名黑名单：.env、私钥、证书等拒绝读取，避免送进 LLM 造成泄露

### 防线 3：Prompt 注入防护（services/workers/base.py）

📍 `services/workers/base.py`：Prompt 注入防护

本项目未单独实现 Prompt 注入检测中间件（无 `base.py`），防护体现在架构层面：

- **supervisor 的审查 prompt 中固化输出格式**：要求 LLM 按 JSON finding 格式输出，不执行代码
- **审查而非执行**：审查的代码永远作为"被分析对象"进入 LLM，不作为指令执行
- **待加固方向**：未来可引入 LLM output 校验层（检查输出是否按 JSON schema，拒绝非结构化内容）

### 防线 4：MCP BearerAuthMiddleware（mcp/server.py）

📍 `mcp/server.py`：`BearerAuthMiddleware`

```python
class _BearerAuthMiddleware:
    """ASGI 层 Bearer 鉴权。不缓冲响应体，流式/SSE 透传。"""
    async def __call__(self, scope, receive, send):
        if scope.get("type") == "http":
            token = self._extract_token(scope)
            if not self.verify(token):
                await self._send_401(send)
                return
        await self.app(scope, receive, send)

def _verify_mcp_token(token) -> bool:
    if not settings.API_AUTH_REQUIRED:
        return True                # 开发态放行
    return is_valid_token(token)   # 生产态要求有效 JWT
```

**为什么不用 FastAPI dependency**：MCP 走 FastMCP 的 streamable-http 传输，不是普通 FastAPI 路由，无法挂 Depends。所以在 ASGI 层拦截——**不缓冲响应体**（流式/SSE 透传，不影响 MCP 传输性能）。

`verify` 闭包实时读 `settings.API_AUTH_REQUIRED`，开发态直接放行，生产态验证 JWT。

## 第三级：安全护栏与告警

### 生产态默认密钥告警（lifespan）

```python
if settings.API_AUTH_REQUIRED and settings.JWT_SECRET.startswith("dev-insecure-secret"):
    logger.warning("⚠️ JWT_SECRET 仍是默认值，可被轻易伪造！")
```

当 `API_AUTH_REQUIRED=True` 但 JWT_SECRET 未自定义时，启动时醒目告警，防止误部署。

### Webhook body 限流

```python
_MAX_WEBHOOK_BODY = 1_000_000  # 1MB
```

验签前即按 Content-Length 或流式累加拒绝超大 body，攻击面最小化。

## Q&A

**Q1：四道防线分别防什么？**  
**A**：CLI（路径穿越+敏感文件）、Webhook（空 secret 免鉴权）、API（JWT 未授权访问）、MCP（JWT 未授权调用）。四个外部触发面全部闭环。

**Q2：MCP 为什么不能用 FastAPI Depends 做鉴权？**  
**A**：MCP 走 FastMCP streamable-http，是独立 ASGI 子应用。FastAPI 的 Depends 注入只对 FastAPI 路由生效，对 mounted sub-app 不生效。鉴权必须在 ASGI 层手写中间件。
