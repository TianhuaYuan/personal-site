# 历史问答管理（搜索 + 清空 + 删单条）

> 让  从「只能问 + 只能看」升级成「能搜 + 能删 + 能清空」的完整  体验。看似简单的增删改查，里面藏着一堆权衡。

## 一、需求

- 后端：清空问答、删单条、关键词搜索
- 前端：搜索框（防抖 300ms）+ 清除历史按钮（二次确认）+ 单条删除（ 显示）

## 二、技术方案与设计决策

### 1. 硬删除  软删除

选硬删除。理由：问答记录不需要审计，软删除会让所有查询多一个 `WHERE deleted_at IS NULL`。类比：扔垃圾桶  扔储物间——储物间东西多了比客厅还乱。

### 2. 越权返回  不是

用户  删用户  的记录 → 返回 404。理由：404 = "没这东西"，403 = "有但你不能动"——返回  会泄露"这条记录存在"。实现上一条  搞定：

```python
result = await db.execute(
    delete(QAHistory)
    .where(QAHistory.id == qa_id, QAHistory.user_id == user_id)
)
return result.rowcount > 0  # 非本人 → rowcount=0 → 端点抛 404
```

类比：快递柜取件——输入别人的取件码，柜子不会说"这不是你的"，只会说"取件码无效"。

### 3.  而非全文索引

数据量小（<100 条），`ilike` 足够快。YAGNI 原则——先简单实现。SQLAlchemy 参数化防止  注入。

### 4. 防抖

输入"Python"6 个字母只发  个请求，不是  个。300ms 是业内常用值。

### 5. 二次确认只加在清除历史

单条删除影响小，弹框打断操作；清除历史不可逆，必须确认。这是典型的「破坏性操作成本  用户摩擦」权衡。

### 6.  抽成通用组件

未来删除简历、注销账号都需要二次确认，一次写好测试零成本复用。

## 三、踩坑

**1. 后端 422：form data vs JSON** — 注册接口要求 JSON body，错用了 `data={}`。教训：看  里现有  的格式，别凭记忆写。

**2.  不阻止 fireEvent.click** —  的 `disabled` 不阻止 `fireEvent.click`（测试工具能绕过）。必须在 `onClick` 里加  守卫：`onClick={() => !loading && onConfirm()}`。

**3.  需要  包裹** — 只有 `MemoryRouter` 不够，必须加 `Routes` + `Route` 定义路由匹配规则，`useParams` 才知道 `:id` 从哪来。

**4. vi.clearAllMocks 不重置 mockResolvedValue** — `clearAllMocks` 只清调用记录不重置实现。三个层次：clear（清调用）＜ reset（重置实现）＜ restore（恢复原始）。

**5.  没有 scrollIntoView** — 测试环境需主动 mock：`Element.prototype.scrollIntoView = vi.fn()`。

## 四、关键代码

### user_id 隔离删除

```python
# WHERE id = ? AND user_id = ? 一条SQL同时做"找记录"和"鉴权"
result = await db.execute(
    delete(QAHistory)
    .where(QAHistory.id == qa_id, QAHistory.user_id == user_id)
)
```

### 防抖实现

```tsx
useEffect(() => {
  if (debounceRef.current) clearTimeout(debounceRef.current);
  debounceRef.current = setTimeout(() => setDebouncedKeyword(keyword), 300);
  return () => { if (debounceRef.current) clearTimeout(debounceRef.current); };
}, [keyword]);
```

拆成两个 useEffect：一个防抖更新 keyword，一个响应变化加载数据。单一职责。

### 搜索时保留  消息

```tsx
setChat((prev) => {
  const streamingMsgs = prev.filter((m) => m.streaming);
  return [...streamingMsgs, ...historyItems];
});
```

如果不保留，用户在搜索时刚发的  消息会被冲掉——很容易忽略的 edge case。
